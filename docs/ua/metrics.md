# Метрики

`include/sensor_fusion/ekf/metrics.h` міряє прогін фільтра відносно еталонної траєкторії. Кожна метрика — окрема невелика функція, тож нова метрика означає ще одну функцію й ще одне поле у `FusionMetrics`. `ComputeFusionMetrics()` рахує той самий набір, що друкує `foreign_impl/ref_ekf.py`, і тим самим способом, тож числа C++ і Python можна порівнювати.

## Вхід

`FusionRuns` містить еталон, усі фікси GNSS і три прогони фільтра на тих самих кроках IMU:

- `full`: з усіма фіксами;
- `outage`: з вирізаними фіксами вікна відключення;
- `imu_only`: без жодного фікса, тобто чисте числення шляху.

Кожен прогін має містити одну оцінку на кожен зразок еталона, у ті самі моменти. Інакше `ComputeFusionMetrics()` повертає `std::nullopt`.

`TimeWindow` — напіввідкритий проміжок `[start, end)`, як у `cut_outage()` з `ref_ekf.py`.

## Набір

| Поле | Значення | `ref_ekf.py` |
| --- | --- | --- |
| `raw_gnss_rmse` | RMSE кожного фікса відносно еталона в його момент | `Raw GNSS RMSE` |
| `filter_rmse` | RMSE `full` на всіх кроках | `EKF full RMSE (route)` |
| `filter_rmse_reduction` | `1 - filter_rmse / raw_gnss_rmse`; 0.3 означає на 30% нижче сирого GNSS, критерій успіху 2 | `% below raw` |
| `outage_rmse` | RMSE `outage` на всіх кроках | `EKF outage RMSE (route)` |
| `outage_window_rmse` | RMSE `outage` на кроках усередині вікна | `EKF outage RMSE (window)` |
| `imu_only_window_rmse` | RMSE `imu_only` на тих самих кроках | `Dead reckoning RMSE (window)` |
| `reacquisition` | див. нижче; критерій успіху 3 | `Error just before reacquisition` |

`reacquisition` — це крок перед першою оцінкою в момент кінця вікна або пізніше, яка використала фікс. Цей крок найдовше дрейфував без поправки. Поле містить:

- `t`;
- `filter_error`, похибку `outage` на цьому кроці;
- `imu_only_error`, похибку `imu_only` на цьому кроці;
- `ratio = imu_only_error / max(filter_error, 1e-9)`.

Значення, яке нема з чого рахувати, дорівнює `std::nullopt` (`null` у JSON), а не нулю: коли немає фіксів, жодного кроку у вікні або фікса після нього.

## Інтерполяція

Фікс рідко припадає точно на крок IMU, тож для `raw_gnss_rmse` потрібен еталон між зразками. `ReferencePositionAt()` повторює `numpy.interp()`:

- перше положення до першого зразка;
- останнє положення після останнього;
- сам зразок, якщо момент на нього припадає;
- `slope * (t - t0) + y0` між зразками.

Збірка numpy для arm64 обчислює останній вираз з одним округленням (злите множення-додавання). `std::fma()` робить те саме на будь-якій платформі, тож результат C++ не залежить від компілятора.

## Збіг із ref_ekf.py

На поїздці 0009, з фіксами від нинішнього `ref_ekf.py`, кожне значення `ComputeFusionMetrics()` збігається з обчисленням у Python до 1e-10 м або точніше. Розкид дають траєкторії, а не метрики. `RunEkf()`, зібраний через clang, збігається з filterpy до 6e-14 м. Зібраний через gcc — до 3e-10 м, бо clang на arm64 зливає множення з додаванням так само, як numpy, а gcc у режимі ISO цього не робить. Обидва результати в межах числової похибки.
