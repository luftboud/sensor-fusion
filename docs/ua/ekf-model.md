# Модель EKF

Двовимірний розширений фільтр Калмана поєднує позицію GNSS із поздовжнім прискоренням і кутовою швидкістю IMU. Ця сторінка фіксує модель один раз. Обидві реалізації, статична `PlanarEkf` і динамічна `PlanarEkfDynamic`, виконують цю модель. Типи стану та сценарію описано в [типах 2D-сценарію](../ekf-scenario.md). Англійська версія — [docs/ekf-model.md](../ekf-model.md), її формули збігаються з цією сторінкою.

## Стан

Стан — вектор-стовпець із чотирьох елементів у такому порядку:

```text
x = [east, north, yaw, v]^T
```

`east` і `north` — метри від початку поїздки. `yaw` — курс у радіанах, 0 вказує на схід, додатний напрямок — проти годинникової стрілки. `v` — знакова швидкість уперед у м/с. Швидкості за координатами — `v cos(yaw)` і `v sin(yaw)`. Стан — це `State2d` у `state.h`.

Коваріація — `P`, симетрична матриця 4×4. Фільтр зберігає квадратний корінь `L` з `P = L L^T`, тож `P` ніколи явно не формується. `L` — та матриця, яку тримає код.

## Вхідні дані і шуми

Одне показання IMU `(ax, wz)` тримається на інтервалі `[t_k, t_{k+1})`, довжина кроку — `dt = t_{k+1} - t_k`:

- `ax` — питоме прискорення вперед уздовж осі x кузова (м/с²).
- `wz` — кутова швидкість навколо осі z кузова (рад/с). Додатна значення повертає ліворуч.

Дві густини шуму процесу, `sigma_a` (`accel_noise_density`) і `sigma_w` (`gyro_noise_density`), задають шум приросту за один крок:

```text
шум приросту швидкості:  dv ~ N(0, sigma_a^2 dt)
шум приросту курсу:      dpsi ~ N(0, sigma_w^2 dt)
Q = diag(sigma_a^2 dt, sigma_w^2 dt)
```

Фікс GNSS дає схід і північ з незалежним шумом стандартного відхилення `sigma_g` (`gnss_position_std`):

```text
z = [east_fix, north_fix]^T,   R = sigma_g^2 I_2
```

Апріорна коваріація діагональна: `sigma_p` (`initial_position_std`) для сходу і півночі, `sigma_psi` (`initial_yaw_std`) для курсу, `sigma_v` (`initial_speed_std`) для швидкості:

```text
P0 = diag(sigma_p^2, sigma_p^2, sigma_psi^2, sigma_v^2)
```

## Прогноз

Нехай `psi_m = yaw + wz dt / 2` — курс у середині кроку, а `d = (v + ax dt / 2) dt` — відстань за крок. Нелінійний крок такий:

```text
east'  = east + d cos(psi_m)
north' = north + d sin(psi_m)
yaw'   = yaw + wz dt
v'     = v + ax dt
```

Якобіан `F = df/dx` — одиничний, окрім чотирьох елементів:

```text
F[east, yaw]   = -d sin(psi_m)
F[north, yaw]  =  d cos(psi_m)
F[east, v]     =  dt cos(psi_m)
F[north, v]    =  dt sin(psi_m)
```

Шум входить через прирости швидкості й курсу, і кожен приріст також зсуває позицію середини кроку на половину. Матриця шуму `G` зі стовпцями для приросту швидкості та приросту курсу:

```text
G = [ 0.5 F[east, v]    0.5 F[east, yaw]
      0.5 F[north, v]   0.5 F[north, yaw]
      0                 1
      1                 0 ]
```

Оновлення коваріації:

```text
P' = F P F^T + G Q G^T
```

У квадратно-корінній формі фільтр будує масив 4×6 `A = [F L | G diag(sigma_a sqrt(dt), sigma_w sqrt(dt))]`. Для кожного рядка він застосовує обертання Гівенса до стовпців, які обнуляють елементи після діагоналі цього рядка. Перші чотири стовпці тоді утворюють новий нижньотрикутний множник `L'`, і `L' L'^T = A A^T = P'`. Обертання зберігають `A A^T`, тож множник лишається квадратним, а коваріація ніколи не формується.

## Оновлення

Фікс GNSS оновлює одну вісь за раз: спершу схід, потім північ, або навпаки, якщо північ має більше стандартне відхилення. Для осі `a` рядок спостереження `H = e_a^T`, нев'язка `nu = z_a - x_a`, дисперсія нев'язки `S = P[a, a] + sigma_g^2`. Коефіцієнт підсилення і оновлення:

```text
K  = P H^T / S
x' = x + K nu
P' = P - K H P
```

У квадратно-корінній формі фільтр будує масив 5×5

```text
[ sigma_g   L[a, :]
  0         L      ]
```

де `L[a, :]` — рядок `a` матриці `L`. Він обертає перший рядок, доки хвіст рядка не стане нульовим. Перший елемент цього рядка тоді дорівнює `sqrt(S)`, а перший стовпець під ним — `sqrt(S) K`. Нижній правий блок 4×4 — множник `P'`, `P' = L' L'^T`. Фільтр зберігає цей блок як є, не обнуляючи верхню частину.

Коефіцієнт підсилення `K = c / sqrt(S)`, де `c` — перший стовпець під опорним елементом. Якщо сам `K` переповнився б або впав у нуль, фільтр замість цього множить `c` на `nu / sqrt(S)`, щоб поправка лишалась скінченною. Звітні стандартні відхилення: `std_east = ||L[east, :]||` і `std_north = ||L[north, :]||`; вони дорівнюють `sqrt(P[east, east])` і `sqrt(P[north, north])`.

## Крокування за часом

`RunEkf` і `RunEkfDynamic` виконують один і той самий цикл. Початковий стан — у `imu[0].t`. Фікс, чий час дорівнює `imu[0].t`, застосовується на початку, а оцінка на цей час позначається як `updated`. Для кожного наступного кроку IMU `[t, t_end)` обробляються всі фікси з `fix.t <= t_end` у порядку часу. Перед кожним фіксом фільтр прогнозує від поточного часу до `fix.t`, а потім застосовує оновлення. Після останнього фіксу фільтр прогнозує до `t_end`. Оцінка на `t_end` позначається як `updated`, якщо в цьому кроці оброблено хоча б один фікс. Фікси раніше за `imu[0].t` або пізніше за останнє показання IMU ігноруються.

## Інтерфейс

```cpp
std::vector<EkfEstimate> RunEkf(std::span<const PlanarImu> imu,
                                std::span<const GnssFix> gnss,
                                const EkfConfig& config = {});

std::vector<EkfEstimate> RunEkfDynamic(std::span<const PlanarImu> imu,
                                       std::span<const GnssFix> gnss,
                                       const DynamicEkfConfig& config = {});
```

`EkfConfig` містить початковий стан, стандартні відхилення та густини шуму, перелічені вище. `DynamicEkfConfig` містить `EkfConfig` як `filter` та `state_size`, що для цієї 2D-моделі має дорівнювати 4. Обидві функції повертають по одній `EkfEstimate` на кожне показання IMU. Кожна оцінка має `t`, `state`, `std_east`, `std_north` і `updated`.

Обидва ряди мають містити скінченні значення і строго зростаючі часи. Порожній GNSS дає траєкторію лише за IMU. Обидві функції кидають `std::invalid_argument` для некоректних входів або конфігурації. Вони кидають `std::overflow_error` або `std::runtime_error`, якщо стан або коваріація переповнюються з робочою точністю.

## Реалізації

Обидві реалізації виконують один і той самий алгоритм: той самий прогноз, те саме редукування Гівенса, те саме оновлення і ті самі перевірки входів. Спільний шаблон `PlanarEkfCore<Policy>` у `ekf.h` містить цей код один раз. Тип матриць задає політика.

| | Статична `PlanarEkf` | Динамічна `PlanarEkfDynamic` |
| --- | --- | --- |
| Заголовок | `include/sensor_fusion/ekf/ekf.h` | `include/sensor_fusion/ekf/ekf_dynamic.h` |
| Тип матриць | `Matrix<double, N, M>` з розмірами в типі | `Matrix<double, 0, 0>` з розмірами, заданими під час створення |
| Виділення пам'яті | Немає на шляху фільтра | Кожен крок виділяє свої матриці в купі |
| Інтерфейс | `RunEkf(imu, gnss, EkfConfig)` | `RunEkfDynamic(imu, gnss, DynamicEkfConfig)` |
| Розмір стану | 4, фіксований типом | З `DynamicEkfConfig::state_size`, що має дорівнювати 4 |

Що спільне: модель, формули, числа, перевірки і винятки. Тести проганяють ті самі сценарії через обидві реалізації. Вони також перевіряють, що на синтетичній поїздці та кількох seed найбільша різниця стану, стандартного відхилення, часу й `updated` не перевищує `1e-9`.

## Відомі обмеження

- Модель планарна. Тангаж, крен і висота не враховуються. Поздовжнє `ax` містить частку гравітації, коли машина нахиляється.
- Курс безпосередньо не спостерігається. GNSS-курсу немає, тож курс і швидкість спостерігаються лише через траєкторію позиції.
- Станів зміщення сенсорів немає. Шум білий, густини фіксовані.
- Перевірки на викиди (gating) немає. Викид GNSS приймається повністю.
- Фільтр вважає фікси сходу та півночі незалежними з однаковим стандартним відхиленням. Корельовані або різні похибки не моделюються.
- Розмір стану в обох реалізаціях — 4. Динамічний фільтр з іншим розміром відхиляється, бо модель такого розміру не визначає.
- Динамічна реалізація виділяє пам'ять на кожному кроці. Її швидкість не є метою цієї реалізації.
- Редукування Гівенса працює з квадратно-корінним множником напряму. Множник після оновлення зберігається як повернутий, тож його верхній трикутник не обнуляється.
